# Kontor 2.0 – Ausbaustufe

Version 2.0 bündelt drei Bausteine und skizziert den weiteren Weg.

## Was in 2.0 enthalten ist

### 1. Hell-/Dunkel-Ansicht
- Umschalter in der Kopfzeile: **System → Hell → Dunkel** (ohne Neuladen).
- Auswahl liegt pro Browser in `app.storage.user['theme']`.
- Zentralisiert in [`app/theme.py`](../app/theme.py): Farben, Stylesheet und der
  NiceGUI-Dark-Mode-Schalter. Dunkel-Overrides auch für die genutzten
  Quasar-Hilfsklassen (`text-grey-*`, `bg-*-1`, `border-*-2`).

### 2. Einstellungsbereich (`/settings`)
- **GitHub**: Standard-Repo und Token – überschreiben `GITHUB_REPO` /
  `GITHUB_TOKEN`.
- **Vorgaben**: Währungssymbol, Wochenstunden neuer Crew, Sprint-Länge.
- **Einstieg & Hilfe**: Willkommens-Dialog an/aus, pro Browser erneut zeigen.
- **Daten**: JSON-Export, Import (ersetzt den Bestand), Demo neu laden,
  alles leeren.
- **Info**: Version, Datenschema, Datensatz-Zahlen.
- Persistenz: `pm.json` → `settings`; Zugriff über
  `store.setting()` / `store.set_setting()` / `store.update_settings()`.
  Kein Schema-Bump – fehlende Schlüssel kommen aus `DEFAULT_SETTINGS`.

### 3. Module je Projekt (`/modules`)
- Jeder Menüpunkt ist ein „Modul" (identifiziert über seinen Pfad).
- Pro Projekt aus-/einblendbar; gespeichert als `Project.disabled_modules`
  (leer = alles sichtbar, neue Module erscheinen automatisch).
- **Kernmodule** (`store.CORE_MODULES`) bleiben immer sichtbar:
  Leitstand, Fahrplan, Rollen, Anleitung, Projekte, Crew, Module, Einstellungen.
- Vorlagen: *Alles*, *Schlank (kleines Team)*, *Nur Delivery*.
- Wirkung: `components.frame()` filtert die Navigation; wird ein ausgeblendeter
  Bereich direkt aufgerufen, erscheint ein Hinweis mit Link zu `/modules`.

## Weiterer Ausbau (Backlog, grob priorisiert)

### Naheliegend
1. **Modul-Registry statt NAV_GROUPS-Liste** – eine `modules.py` mit
   `Module(key, label, icon, group, core, description, deps)` als einzige
   Quelle; `main.ROUTES`, Navigation und `/modules` daraus ableiten.
   Ermöglicht Abhängigkeiten (z. B. „Burndown" braucht „Sprints").
2. **Dashboard-Kacheln modulabhängig** – Panels auf dem Leitstand (Betrieb,
   Risiken, Releases) nur zeigen, wenn das Modul aktiv ist.
3. **Standard-Module pro Projekttyp** – beim Anlegen eines Projekts einen Typ
   wählen (Intern / Kundenprojekt / Wartung), der ein Preset setzt.
4. **Pro-Projekt-Theme** – Akzentfarbe des Projekts (`Project.color`) auf die
   Oberfläche durchschlagen lassen.
5. **Einstellungen aufteilen** – global vs. pro Projekt sichtbar trennen;
   Modul-Verwaltung als Reiter in die Projekt-Bearbeitung ziehen.

### Mittel
6. **Mehrbenutzer / Rollen** – aktuell ein gemeinsames Passwort. Ziel: Nutzer
   mit Rollen (Leitung / Team / Gast), pro-Nutzer-Sicht auf „meine Aufgaben",
   Audit-Log für Änderungen. Bedingt einen echten Session-Store.
7. **Datenschicht wechselbar** – `Store` hinter ein Interface legen, damit
   neben JSON auch SQLite möglich ist (Nebenläufigkeit, größere Datenmengen).
   JSON bleibt Default und Export-Format.
8. **Benachrichtigungen** – fällige Meilensteine, überzogene Sprints, neue
   Blocker per E-Mail / Webhook (z. B. in einen Chat-Kanal).
9. **Vorlagen & Duplizieren** – Projekt aus Vorlage anlegen (Charter, DoD,
   Standard-Risiken, RACI-Gerüst); Sprint-Retro-Vorlagen.
10. **API / Read-only-JSON** – `/api/status/<projekt>` für externe Dashboards
    und Statusberichte.

### Später
11. **Import aus GitHub** – Issues/Milestones als Tasks/Sprints übernehmen,
    nicht nur die PR-Sicht.
12. **Zeitreihen & Historie** – Snapshots des Projekt-Gesundheitswerts, damit
    Trends (Velocity, Stimmung, Bugs) über Monate sichtbar werden.
13. **Mehrsprachigkeit** – Textkatalog aus dem UI-Code ziehen (Deutsch bleibt
    Default).
14. **Mobile-Ansicht** – Fahrplan + Standup + Board als kompakte Ansicht.

## Migrationshinweise

- `Project.disabled_modules` und `settings` sind additive Felder – bestehende
  `pm.json` funktioniert unverändert weiter (kein `SCHEMA`-Bump).
- Wer die Modul-Registry (Punkt 1) umsetzt, sollte `SCHEMA` erst bei einer
  echten Modelländerung erhöhen; die Pfad-basierten Keys bleiben stabil.
